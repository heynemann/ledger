## Prerequisites

- Go 1.26 or later
- A Go module (`go mod init`)

The steps below use the in-memory store, so you don't need a database to follow along. [Switch to PostgreSQL](#switch-to-postgresql) at the end when you're ready.

## Install

```bash
go get github.com/xraph/ledger@latest
```

## Step 1: Create the engine

`ledger.New` takes a `store.Store` and any number of options. `Start` migrates the store (a no-op for the memory store), then starts the meter flush worker and the lifecycle clock. `Stop` flushes buffered usage, stops the workers and closes the store.

```go
engine := ledger.New(memory.New(),
	ledger.WithMeterConfig(100, 5*time.Second),     // flush every 100 events or every 5s
	ledger.WithEntitlementCacheTTL(30*time.Second), // cache quota answers for 30s
)
if err := engine.Start(ctx); err != nil {
	log.Fatal(err)
}
defer engine.Stop()
```

Those two options are the defaults, so `ledger.New(memory.New())` behaves the same. [Configuration](/docs/concepts/configuration) lists every option.

## Step 2: Create a plan

A plan carries its features, its currency and its pricing. `CreatePlan` validates it, assigns a `plan_` TypeID and stores it. A plan with no `Status` is saved as a draft, and only an active plan takes subscribers, so set `plan.StatusActive` (or call `ActivatePlan` later).

```go
pro := &plan.Plan{
	Name:     "Pro",
	Slug:     "pro",
	Currency: "usd",
	Status:   plan.StatusActive,
	AppID:    "my-app",
	Features: []plan.Feature{
		{Key: "api_calls", Name: "API calls", Type: plan.FeatureMetered, Limit: 10000, Period: plan.PeriodMonthly, SoftLimit: true},
		{Key: "sso", Name: "Single sign-on", Type: plan.FeatureBoolean, Limit: 1},
	},
	Pricing: &plan.Pricing{
		BaseAmount:    types.USD(49_000_000), // $49.000000 (USD micros)
		BillingPeriod: plan.PeriodMonthly,
		Tiers: []plan.PriceTier{
			{FeatureKey: "api_calls", Type: plan.TierGraduated, UpTo: 10000, UnitAmount: types.Zero("usd")},
			{FeatureKey: "api_calls", Type: plan.TierGraduated, UpTo: -1, UnitAmount: types.USD(10_000)}, // 1 cent a call
		},
	},
}
if err := engine.CreatePlan(ctx, pro); err != nil {
	log.Fatal(err)
}
```

The feature's `Limit` does two jobs. It's the quota `Entitled` enforces, and for a metered feature it's also the allowance the invoice includes before overage starts. `SoftLimit: true` lets a tenant go past it and bills the extra through the tiers. A boolean feature is on when its `Limit` is above zero.

## Step 3: Subscribe a tenant

The tenant is the customer you bill: a string you choose, such as an organization ID. The subscription must name it, and its `AppID` must match the plan's.

```go
sub := &subscription.Subscription{TenantID: "acme", AppID: "my-app", PlanID: pro.ID}
if err := engine.CreateSubscription(ctx, sub); err != nil {
	log.Fatal(err)
}
```

`CreateSubscription` fills in the `sub_` ID and the first period, which starts now and runs one billing period. With no `Status` set, the subscription starts as `trialing` when the plan has `TrialDays`, and `active` otherwise.

## Step 4: Check a quota and meter usage

`Entitled`, `Remaining` and `Meter` take the tenant and app from the context values `"tenant_id"` and `"app_id"`, both plain strings.

```go
ctx = context.WithValue(ctx, "tenant_id", "acme")
ctx = context.WithValue(ctx, "app_id", "my-app")

res, err := engine.Entitled(ctx, "api_calls")
if err != nil {
	log.Fatal(err)
}
if !res.Allowed {
	// Respond with 429 or similar. res.Reason says why.
	return
}

// Do the work, then record it.
if err := engine.Meter(ctx, "api_calls", 1); err != nil {
	log.Fatal(err)
}
```

If either value is missing, `Meter` returns `ledger.ErrInvalidInput` and `Entitled` answers not allowed with the reason `"missing tenant or app context"`.

Two timing details are worth knowing early. `Meter` doesn't write on the spot: the event sits in a buffer until the flush worker writes the batch, so it counts toward quota checks and invoices only after that flush. And `Entitled` caches its answer for the cache TTL, so a quota check can lag the latest flush by up to 30 seconds.

## Step 5: Generate an invoice

`GenerateInvoice` bills the subscription's current period: a base fee line, an overage line per metered feature past its allowance, seat lines, discounts from applied coupons and tax from any tax plugin.

```go
inv, err := engine.GenerateInvoice(ctx, sub.ID)
if err != nil {
	log.Fatal(err)
}

fmt.Println("invoice", inv.ID, inv.Status)
for _, li := range inv.LineItems {
	fmt.Printf("  %-8s %-22s %s\n", li.Type, li.Description, li.Amount)
}
fmt.Println("  subtotal", inv.Subtotal, "tax", inv.TaxAmount, "total", inv.Total)
```

A second invoice for a period that already has a live one fails with `ledger.ErrAlreadyExists`. To bill a period that has already ended, pass `ledger.ForPeriod(start, end)`. Ledger never generates invoices by itself, so you decide when to call this, typically from an `OnSubscriptionRenewed` plugin hook or your own scheduler. See [Billing cycles](/docs/subsystems/billing-cycles).

## Step 6: Finalize and record payment

An invoice starts as a draft. `FinalizeInvoice` moves it to `pending` and sets a due date 30 days out. Once your payment provider has collected the money, record it:

```go
if err := engine.FinalizeInvoice(ctx, inv.ID); err != nil {
	log.Fatal(err)
}
if err := engine.MarkInvoicePaid(ctx, inv.ID, time.Now(), "ch_123"); err != nil {
	log.Fatal(err)
}
```

The lifecycle clock marks a pending invoice `past_due` once its due date passes.

## Complete example

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/xraph/ledger"
	"github.com/xraph/ledger/plan"
	"github.com/xraph/ledger/store/memory"
	"github.com/xraph/ledger/subscription"
	"github.com/xraph/ledger/types"
)

func main() {
	ctx := context.Background()

	engine := ledger.New(memory.New())
	if err := engine.Start(ctx); err != nil {
		log.Fatal(err)
	}
	defer engine.Stop()

	pro := &plan.Plan{
		Name:     "Pro",
		Slug:     "pro",
		Currency: "usd",
		Status:   plan.StatusActive,
		AppID:    "my-app",
		Features: []plan.Feature{
			{Key: "api_calls", Name: "API calls", Type: plan.FeatureMetered, Limit: 10000, Period: plan.PeriodMonthly},
			{Key: "sso", Name: "Single sign-on", Type: plan.FeatureBoolean, Limit: 1},
		},
		Pricing: &plan.Pricing{
			BaseAmount:    types.USD(49_000_000),
			BillingPeriod: plan.PeriodMonthly,
		},
	}
	if err := engine.CreatePlan(ctx, pro); err != nil {
		log.Fatal(err)
	}

	sub := &subscription.Subscription{TenantID: "acme", AppID: "my-app", PlanID: pro.ID}
	if err := engine.CreateSubscription(ctx, sub); err != nil {
		log.Fatal(err)
	}

	ctx = context.WithValue(ctx, "tenant_id", "acme")
	ctx = context.WithValue(ctx, "app_id", "my-app")

	for i := range 3 {
		res, err := engine.Entitled(ctx, "api_calls")
		if err != nil {
			log.Fatal(err)
		}
		if !res.Allowed {
			fmt.Println("quota exceeded at request", i+1)
			break
		}
		if err := engine.Meter(ctx, "api_calls", 1); err != nil {
			log.Fatal(err)
		}
	}

	inv, err := engine.GenerateInvoice(ctx, sub.ID)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("invoice", inv.ID, "total", inv.Total)

	if err := engine.FinalizeInvoice(ctx, inv.ID); err != nil {
		log.Fatal(err)
	}
	if err := engine.MarkInvoicePaid(ctx, inv.ID, time.Now(), "manual"); err != nil {
		log.Fatal(err)
	}
}
```

Run it with `go run .` and it prints the invoice ID and a total of `$49.000000`, the base fee: three calls are well inside the 10,000 allowance.

## Switch to PostgreSQL

The PostgreSQL, SQLite and MongoDB stores all take a `*grove.DB`. Open a Grove driver, wrap it, and hand the store to `ledger.New`:

```go
pg := pgdriver.New()
if err := pg.Open(ctx, os.Getenv("DATABASE_URL")); err != nil {
	log.Fatal(err)
}

db, err := grove.Open(pg)
if err != nil {
	log.Fatal(err)
}

engine := ledger.New(postgres.New(db))
if err := engine.Start(ctx); err != nil { // runs the store's migrations first
	log.Fatal(err)
}
defer engine.Stop() // also closes db
```

The imports are `github.com/xraph/grove`, `github.com/xraph/grove/drivers/pgdriver` and `github.com/xraph/ledger/store/postgres`. See [PostgreSQL store](/docs/stores/postgres).
