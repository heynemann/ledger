---
title: Memory Store
description: The in-memory store, for tests and local development.
---

`store/memory` keeps everything in Go maps behind one `sync.RWMutex`. It's safe for concurrent use and loses everything when the process exits. Use it for unit tests, examples and local development, and as the reference behaviour when you write a store of your own: it passes the same conformance suite as the database stores.

## Setup

```go
import "github.com/xraph/ledger/store/memory"

engine := ledger.New(memory.New(),
	ledger.WithMeterConfig(1, 10*time.Millisecond), // write each event almost at once
	ledger.WithEntitlementCacheTTL(0),               // cache entries expire immediately
)
```

Keep the flush interval positive: `Start` panics on a zero or negative one. Even with a batch size of 1, the flush runs on the worker goroutine, so a test that meters and then checks usage still has to wait for it.

## What it holds

```go
type Store struct {
	mu sync.RWMutex

	plans              map[string]*plan.Plan
	subscriptions      map[string]*subscription.Subscription
	usageEvents        []meter.UsageEvent
	entitlementCache   map[string]*entitlement.Result
	cacheExpiry        map[string]time.Time
	invoices           map[string]*invoice.Invoice
	coupons            map[string]*coupon.Coupon
	couponApplications map[string][]*coupon.Application
	features           map[string]*feature.Feature
}
```

The fields are unexported. The store copies plans, subscriptions and other entities on the way in and out, so editing a struct you got back doesn't change what's stored.

## Behaviour

It implements all of `store.Store`, including the lifecycle queries, so the lifecycle clock and `Advance` work against it. A few details:

- `Migrate`, `Ping` and `Close` do nothing and return nil.
- Usage totals for quota checks start at the beginning of the current UTC calendar month (or year, for a yearly feature), and cover all time for a feature with no period.
- A usage event with a non-empty `IdempotencyKey` that's already stored is skipped.
- The entitlement cache honours the TTL like the database stores do.
- Coupon redemption checks the cap and records the application under the store's lock, as one step.

## Testing patterns

### Basic test setup

```go
func TestBillingFlow(t *testing.T) {
	engine := ledger.New(memory.New())

	ctx := context.WithValue(t.Context(), "tenant_id", "test-tenant")
	ctx = context.WithValue(ctx, "app_id", "test-app")

	if err := engine.Start(ctx); err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { _ = engine.Stop() })

	p := &plan.Plan{
		Name:     "Test",
		Slug:     "test",
		Currency: "usd",
		Status:   plan.StatusActive,
		AppID:    "test-app",
		Features: []plan.Feature{
			{Key: "api_calls", Type: plan.FeatureMetered, Limit: 100, Period: plan.PeriodMonthly},
		},
	}
	if err := engine.CreatePlan(ctx, p); err != nil {
		t.Fatal(err)
	}

	// Subscribe, check entitlements, meter, invoice...
}
```

A plan needs a name, a slug and a currency, and only an active plan takes subscribers.

### Pinning the clock

`ledger.WithClock` drives the lifecycle and period decisions, so a test can create a subscription and then call `Advance` with a time past its period end:

```go
now := time.Date(2026, 1, 15, 0, 0, 0, 0, time.UTC)
engine := ledger.New(memory.New(),
	ledger.WithClock(func() time.Time { return now }),
	ledger.WithLifecycleInterval(0), // drive Advance yourself
)

// ... create a plan and a subscription, then:
report, err := engine.Advance(ctx, now.AddDate(0, 1, 1))
```

Usage events keep wall-clock timestamps and the store's quota windows use the wall clock, so `WithClock` doesn't move those.

### Plugins in tests

```go
recorder := audithook.RecorderFunc(func(_ context.Context, ev *audithook.AuditEvent) error {
	events = append(events, ev.Action)
	return nil
})

engine := ledger.New(memory.New(),
	ledger.WithPlugin(audithook.New(recorder)),
)
```

## Compared with the PostgreSQL store

| | Memory | PostgreSQL |
|---|--------|-----------|
| Persistence | None | Full |
| More than one process | No | Yes |
| Migrations | No-op | Grove migrations |
| Setup | None | A database and a DSN |
| Tenant and app filtering | In the map scans | In the SQL `WHERE` clauses |
