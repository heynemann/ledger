---
title: MongoDB Store
description: The MongoDB store, on Grove's mongodriver.
---

`store/mongo` implements `store.Store` on a `*grove.DB` opened with Grove's MongoDB driver. Each entity is a document in its own collection. It doesn't use multi-document transactions, so it runs against a standalone `mongod` as well as a replica set.

## Setup

```go
import (
	"github.com/xraph/grove"
	"github.com/xraph/grove/drivers/mongodriver"
	"github.com/xraph/ledger"
	"github.com/xraph/ledger/store/mongo"
)

mdb := mongodriver.New()
if err := mdb.Open(ctx, "mongodb://localhost:27017/ledger"); err != nil {
	log.Fatal(err)
}

db, err := grove.Open(mdb)
if err != nil {
	log.Fatal(err)
}

engine := ledger.New(mongo.New(db))
if err := engine.Start(ctx); err != nil { // creates indexes first
	log.Fatal(err)
}
defer engine.Stop() // closes the store, which closes db
```

The database name comes from the URI's path. If the URI has none, pass `mongodriver.WithDatabase("ledger")` to `Open`.

## Migrations

`engine.Start` calls the store's `Migrate`, which creates the indexes every collection needs and then drops any index a newer one replaced. It doesn't install JSON Schema validation. Running it again is safe.

The package also exports `mongo.Migrations`, a Grove migration group that creates the collections and indexes. `Migrate` doesn't use it; it's there if you run Grove's migration orchestrator yourself.

## Collections

`ledger_plans`, `ledger_features`, `ledger_subscriptions`, `ledger_usage_events`, `ledger_entitlement_cache`, `ledger_invoices`, `ledger_coupons` and `ledger_coupon_applications`.

Usage events have a partial unique index on `idempotency_key` that only covers non-empty keys, so a repeated key is skipped and events without one never collide.

## Coupon redemption

Without a transaction, `RedeemCoupon` takes two writes: it inserts the application, then increments the redemption count with a conditional update that enforces the cap. If the increment fails, it deletes the application again. The SQL stores do both in one transaction. The gap matters only under heavy concurrent redemption of a capped coupon, or a crash between the two writes, which can leave an application with no matching count.

## Characteristics

| Aspect | Detail |
|--------|--------|
| Driver | Grove with `mongodriver` |
| Migrations | Index creation in `Migrate`; `mongo.Migrations` for Grove's orchestrator |
| Transactions | None needed; single-document writes and conditional updates |
| `Ping` | `db.Ping(ctx)` |
| `Close` | Closes the `*grove.DB` |

## Testing against it

The conformance suite in `store/storetest` runs against MongoDB when `LEDGER_TEST_MONGO_URI` is set, and skips otherwise.

## When to use

- MongoDB is already your primary database.
- You want document storage for plans and invoices without a separate SQL server.
