---
title: SQLite Store
description: Lightweight SQLite store for development, testing, and single-node Ledger deployments.
---

The `store/sqlite` package implements Ledger's `store.Store` interface using the grove ORM with the SQLite driver. It requires no external database process, making it ideal for development, integration tests, and single-node deployments.

## Setup

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/sqlitedriver"
    "github.com/xraph/ledger"
    "github.com/xraph/ledger/store/sqlite"
)

sdb := sqlitedriver.New()
if err := sdb.Open(ctx, "file:ledger.db?_pragma=busy_timeout(5000)"); err != nil {
    log.Fatal(err)
}

db, err := grove.Open(sdb)
if err != nil {
    log.Fatal(err)
}

s := sqlite.New(db)

engine := ledger.New(s,
    ledger.WithMeterConfig(100, 5*time.Second),
)

// Start runs migrations automatically
if err := engine.Start(ctx); err != nil {
    log.Fatal(err)
}
defer engine.Stop() // closes the store, which closes db
```

Keep the `busy_timeout` pragma in your DSN: without it, concurrent coupon redemptions fail with a raw `database is locked (SQLITE_BUSY)` error instead of waiting their turn and returning `ErrCouponExhausted` when the cap is reached.

For tests, point the same DSN at a file in the test's temp directory:

```go
dsn := "file:" + filepath.Join(t.TempDir(), "ledger.db") + "?_pragma=busy_timeout(5000)"
```

Don't use `":memory:"`. The driver opens the database through a connection pool, and every pooled connection to `":memory:"` gets its own empty database, so a write on one connection is invisible to the next. `store/storetest/harness.go` opens its test stores exactly this way and explains why in `NewSQLite`.

## Migrations

`engine.Start()` calls the store's `Migrate`, which runs the `sqlite.Migrations` group through Grove's migration orchestrator. Grove records which migrations have run, so it's safe on every start. To migrate on your own schedule, call `s.Migrate(ctx)` yourself and pass `ledger.WithoutMigrate()` to the engine:

```go
if err := s.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

The tables match the [PostgreSQL store](/docs/stores/postgres#tables), with SQLite column types.

## Implements `store.Store`

```go
// Compile-time check
var _ store.Store = (*Store)(nil)
```

## Characteristics

| Aspect | Detail |
|--------|--------|
| Driver | grove ORM + sqlitedriver |
| Migrations | grove orchestrator with programmatic migrations |
| Coupon redemption | Cap check, count and application written as one unit |
| Concurrency | One writer at a time; `busy_timeout` makes other writers wait |
| Persistence | File-based |
| `Close` | Closes the `*grove.DB` |

## When to use

- Development and local testing without external dependencies.
- Single-process or embedded billing deployments.
- CI pipelines where spinning up PostgreSQL is impractical. The conformance suite runs against SQLite on every `go test`.
