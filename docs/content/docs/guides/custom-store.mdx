The engine talks to storage through one interface, `store.Store`. The PostgreSQL, SQLite, MongoDB and memory stores implement it, and so can you: a store for another database, or a wrapper around one of the existing stores that adds caching or tracing.

The interface is large (about sixty methods), and several of them carry concurrency rules the engine depends on. Two habits make this manageable. Read `store/store.go`, whose comments state each method's contract, and copy `store/memory` as your starting point, since it's the simplest complete implementation. Then run the conformance suite until it passes.

## The interface, by group

`store.Store` declares every method itself rather than embedding the per-entity interfaces, so the names carry their entity (`CreatePlan`, `CreateInvoice`).

| Group | Methods |
|-------|---------|
| Plans | `CreatePlan`, `GetPlan`, `GetPlanBySlug`, `ListPlans`, `UpdatePlan`, `DeletePlan`, `ArchivePlan` |
| Catalog features | `CreateFeature`, `GetFeature`, `GetFeatureByKey`, `ListFeatures`, `ListGlobalFeatures`, `UpdateFeature`, `DeleteFeature`, `ArchiveFeature` |
| Subscriptions | `CreateSubscription`, `GetSubscription`, `GetActiveSubscription`, `ListSubscriptions`, `UpdateSubscription`, `CancelSubscription` |
| Operator writes | `PauseSubscription`, `ResumeSubscription`, `ChangeSubscriptionPlan`, `SetSubscriptionProvider` |
| Usage | `IngestBatch`, `Aggregate`, `AggregateMulti`, `QueryUsage`, `PurgeUsage` |
| Entitlement cache | `GetCached`, `SetCached`, `Invalidate`, `InvalidateFeature` |
| Invoices | `CreateInvoice`, `GetInvoice`, `ListInvoices`, `UpdateInvoice`, `GetInvoiceByPeriod`, `ListPendingInvoices`, `MarkInvoicePaid`, `MarkInvoiceVoided`, `SetInvoiceProvider` |
| Coupons | `CreateCoupon`, `GetCoupon`, `GetCouponByID`, `ListCoupons`, `UpdateCoupon`, `DeleteCoupon`, `ApplyCoupon`, `ListAppliedCoupons`, `IncrementCouponRedemptions`, `RedeemCoupon` |
| Lifecycle clock | `ListDueSubscriptions`, `ListOverdueInvoices`, `EndSubscriptionTrial`, `EnactSubscriptionCancel`, `AdvanceSubscriptionPeriod`, `MarkInvoicePastDue` |
| Core | `Migrate`, `Ping`, `Close` |

## Scaffold

```go
package mystore

import (
	"context"

	"github.com/xraph/ledger/store"
)

// Compile-time check: the build fails until every method exists.
var _ store.Store = (*Store)(nil)

type Store struct {
	// your client, pool or handle
}

func New( /* your connection */ ) *Store {
	return &Store{}
}

func (s *Store) Migrate(ctx context.Context) error { return nil } // create your schema
func (s *Store) Ping(ctx context.Context) error    { return nil }
func (s *Store) Close() error                      { return nil } // the engine calls this from Stop
```

## Rules the engine relies on

These come from the interface comments and the conformance suite. Get them wrong and the engine misbehaves in ways a happy-path test won't show.

### Errors

- A missing row returns the entity's sentinel from the root package: `ledger.ErrPlanNotFound`, `ledger.ErrSubscriptionNotFound`, `ledger.ErrFeatureNotFound`, `ledger.ErrInvoiceNotFound`, `ledger.ErrCouponNotFound`. `GetActiveSubscription` returns `ledger.ErrNoActiveSubscription`. The engine checks these with `errors.Is`, for example to tell a free slug from a store failure.
- `GetCached` returns an error (the built-in stores use `ledger.ErrCacheMiss`) for a missing or expired entry. Any error counts as a miss.
- Import the root package as `ledger "github.com/xraph/ledger"`. The memory store does this, so there's no import cycle to worry about.

### Scoping

- List and aggregate methods take a tenant and an app. An empty tenant means every tenant, and an empty app means every app.
- `GetActiveSubscription` returns the newest subscription for the tenant and app whose status is `active` or `trialing`.
- Plan slugs, coupon codes and catalog feature keys are unique per app.

### Usage

- `IngestBatch` skips an event whose non-empty `IdempotencyKey` is already stored, without an error. Events with an empty key never collide with each other.
- `Aggregate` sums `Quantity` for the tenant, app and feature from the start of the period: the current UTC calendar month for `plan.PeriodMonthly`, the year for `plan.PeriodYearly`, and all time otherwise.
- `QueryUsage` returns events in the half-open window `[Start, End)`.

### Conditional writes

The lifecycle clock and operator calls can race, on one process or across replicas. Every method in the operator and lifecycle groups, and `CancelSubscription`, is a single conditional write: its `WHERE` repeats the precondition, it touches only the columns it names, and the bool result reports whether a row matched. A missing row is `false` with no error. Never implement one by reading the row, changing it in Go and writing the whole row back: that's how a clock-advanced period gets put back or a canceled subscription comes back to life.

For example, `AdvanceSubscriptionPeriod(ctx, subID, from, start, end, now)` sets the period to `[start, end)` only when the subscription is `active`, `trialing` or `past_due`, its current period still ends at `from`, that end is at or before `now`, and no cancel falls at or before it. Pinning `from` is what stops two replicas announcing the same renewal.

`CancelSubscription` takes the cancel date from the row inside the same statement (`cancel_at = current_period_end`), not from a value the engine read earlier, and refuses an already canceled or expired subscription with `ledger.ErrSubscriptionCanceled` or `ledger.ErrSubscriptionExpired`.

### Coupons

`RedeemCoupon` records the application and increments `TimesRedeemed` as one unit, with the cap (`MaxRedemptions`, where zero or less means unlimited) enforced by a conditional increment. It returns `ledger.ErrCouponAlreadyApplied` for a second application to the same subscription and `ledger.ErrCouponExhausted` at the cap. `ListAppliedCoupons` returns coupons in the order they were applied, an empty slice for an unknown subscription, and skips coupons that have since been deleted. `UpdateCoupon` never writes `TimesRedeemed`.

### Times

Store times in UTC and give them back at a precision that round-trips: the engine already cuts the times it writes to the millisecond. `AdvanceSubscriptionPeriod` compares `from` with the stored period end for equality, so a value that comes back changed breaks the lifecycle clock.

## Test it with the conformance suite

`store/storetest` holds the same suite every built-in store passes: round trips, tenant and app isolation, coupon redemption under concurrency, the conditional lifecycle and operator writes, and UTC periods. Point it at your store:

```go
package mystore_test

import (
	"testing"

	"github.com/xraph/ledger/store"
	"github.com/xraph/ledger/store/storetest"

	"example.com/mystore"
)

func TestConformance(t *testing.T) {
	storetest.Run(t, func(t *testing.T) store.Store {
		s := mystore.New( /* a fresh, empty database for this subtest */ )
		if err := s.Migrate(t.Context()); err != nil {
			t.Fatal(err)
		}
		t.Cleanup(func() { _ = s.Close() })
		return s
	})
}
```

`Run` calls your function once per subtest, so each starts from a clean database. Run it with `-race`: several subtests drive concurrent writers on purpose.

## Wrapping a built-in store

To add behaviour around an existing store, embed it and override the methods you care about. The embedded store supplies everything else:

```go
type tracedStore struct {
	*postgres.Store
}

func (s tracedStore) IngestBatch(ctx context.Context, events []*meter.UsageEvent) error {
	start := time.Now()
	err := s.Store.IngestBatch(ctx, events)
	log.Printf("ingested %d events in %s", len(events), time.Since(start))
	return err
}

engine := ledger.New(tracedStore{postgres.New(db)})
```
