description: One program that creates a plan, subscribes a tenant, meters usage, applies a coupon and bills the period.

This guide builds one program, step by step: a plan with metered, seat and boolean features, a tenant on that plan, some usage, a coupon, an invoice, and the invoice's way from draft to paid. It uses the in-memory store, so you can paste it into an empty module and run it.

```bash
go get github.com/xraph/ledger@latest
```

## 1. Start the engine

```go
func main() {
	ctx := context.Background()

	engine := ledger.New(memory.New(),
		ledger.WithLogger(log.NewDevelopmentLogger()),
		ledger.WithMeterConfig(50, time.Second),        // flush every 50 events or every second
		ledger.WithEntitlementCacheTTL(30*time.Second), // cache quota answers for 30s
	)
	if err := engine.Start(ctx); err != nil {
		stdlog.Fatal(err)
	}
	defer engine.Stop()

	run(ctx, engine)
}
```

`WithLogger` takes a logger from `github.com/xraph/go-utils/log`, imported here as `log`, so the standard library's `log` is renamed `stdlog`. The one-second flush interval is there so the example doesn't wait long for its usage to land; the default is five.

## 2. Create a plan

```go
	pro := &plan.Plan{
		Name:     "Pro",
		Slug:     "pro",
		Currency: "usd",
		Status:   plan.StatusActive,
		AppID:    "myapp",
		Features: []plan.Feature{
			{Key: "api_calls", Name: "API calls", Type: plan.FeatureMetered, Limit: 10000, Period: plan.PeriodMonthly, SoftLimit: true},
			{Key: "seats", Name: "Seats", Type: plan.FeatureSeat},
			{Key: "priority_support", Name: "Priority support", Type: plan.FeatureBoolean, Limit: 1},
		},
		Pricing: &plan.Pricing{
			BaseAmount:    types.USD(4999), // $49.99 a month
			BillingPeriod: plan.PeriodMonthly,
			Tiers: []plan.PriceTier{
				// API calls: the first 10,000 are in the base fee, then 2 cents each up to 50,000, then 1 cent.
				{FeatureKey: "api_calls", Type: plan.TierGraduated, UpTo: 10000, UnitAmount: types.Zero("usd")},
				{FeatureKey: "api_calls", Type: plan.TierGraduated, UpTo: 50000, UnitAmount: types.USD(2)},
				{FeatureKey: "api_calls", Type: plan.TierGraduated, UpTo: -1, UnitAmount: types.USD(1)},
				// Seats: $10 each.
				{FeatureKey: "seats", Type: plan.TierGraduated, UpTo: -1, UnitAmount: types.USD(1000)},
			},
		},
	}
	if err := engine.CreatePlan(ctx, pro); err != nil {
		stdlog.Fatal(err)
	}
	fmt.Println("plan", pro.ID)
```

Each feature type behaves differently:

- A metered feature's `Limit` is both the quota and the allowance the base fee covers. `SoftLimit: true` lets a tenant go past it, and the tiers price the extra.
- A seat feature is billed from the seat count on the subscription. Every seat is priced through the tiers, and the feature's `Limit` plays no part in the bill.
- A boolean feature is on when its `Limit` is above zero.

Tiers are per feature and must share one type. `UpTo` counts total usage in the period, and `-1` (or `0`) marks the open-ended top tier. `CreatePlan` checks every ladder and fails with `invoice.ErrInvalidTiers` when one is broken, for example a graduated tier carrying a `FlatAmount`.

## 3. Subscribe a tenant

```go
	sub := &subscription.Subscription{
		TenantID: "acme-corp",
		AppID:    "myapp",
		PlanID:   pro.ID,
		Quantity: map[string]int64{"seats": 3},
	}
	if err := engine.CreateSubscription(ctx, sub); err != nil {
		stdlog.Fatal(err)
	}
	fmt.Println("subscription", sub.ID, sub.Status, sub.CurrentPeriodStart.Format(time.DateOnly), "to", sub.CurrentPeriodEnd.Format(time.DateOnly))
```

`CreateSubscription` assigns the `sub_` ID, starts the first period now and ends it one billing period later, and sets the status to `active` (or `trialing` when the plan has `TrialDays`). `Quantity` holds seat counts, and only the plan's seat features may appear in it.

## 4. Record usage

```go
	tenantCtx := context.WithValue(ctx, "tenant_id", "acme-corp")
	tenantCtx = context.WithValue(tenantCtx, "app_id", "myapp")

	for range 150 {
		if err := engine.Meter(tenantCtx, "api_calls", 1); err != nil {
			stdlog.Fatal(err)
		}
	}
	// A bulk import counts the same way: one event carrying 10,500 units.
	if err := engine.Meter(tenantCtx, "api_calls", 10500); err != nil {
		stdlog.Fatal(err)
	}

	// Give the flush worker time to write the buffered events.
	time.Sleep(2 * time.Second)
```

`Meter` is non-blocking. It puts the event on a buffered channel that holds 10,000 events, and returns `ledger.ErrMeterBufferFull` when that's full. The flush worker writes the batch once it has 50 events or every second here, and usage counts toward quotas and invoices only after that write.

## 5. Check entitlements

```go
	res, err := engine.Entitled(tenantCtx, "api_calls")
	if err != nil {
		stdlog.Fatal(err)
	}
	fmt.Printf("api_calls allowed=%t used=%d limit=%d remaining=%d reason=%q\n",
		res.Allowed, res.Used, res.Limit, res.Remaining, res.Reason)

	support, err := engine.Entitled(tenantCtx, "priority_support")
	if err != nil {
		stdlog.Fatal(err)
	}
	fmt.Println("priority_support allowed:", support.Allowed)
```

The tenant has used 10,650 calls against a limit of 10,000, so a hard limit would deny the call. This one is soft, so `Allowed` is true, `Remaining` is 0 and `Reason` is `"over soft limit"`. `Entitled` returns an `entitlement.Result`:

| Field | Type | Meaning |
|-------|------|---------|
| `Allowed` | `bool` | Whether to serve the request |
| `Feature` | `string` | The feature key checked |
| `Used` | `int64` | Usage counted in the feature's quota window |
| `Limit` | `int64` | The plan feature's limit, `-1` for unlimited |
| `Remaining` | `int64` | `Limit - Used`, never below 0, and `-1` when unlimited |
| `SoftLimit` | `bool` | Whether the feature lets usage go past the limit |
| `Reason` | `string` | Why it was denied or flagged, empty otherwise |

The answer is cached for the cache TTL, so asking again within 30 seconds returns the same result even if more usage has landed.

## 6. Apply a coupon

```go
	launch := &coupon.Coupon{
		Code:       "LAUNCH10",
		Name:       "Launch discount",
		Type:       coupon.CouponTypePercentage,
		Percentage: 10,
		AppID:      "myapp",
	}
	if err := engine.CreateCoupon(ctx, launch); err != nil {
		stdlog.Fatal(err)
	}
	if _, err := engine.ApplyCoupon(ctx, sub.ID, "LAUNCH10"); err != nil {
		stdlog.Fatal(err)
	}
```

An applied coupon stays on the subscription and discounts every invoice it gets from then on. Nothing in the engine detaches it; deleting the coupon is the way to stop it.

## 7. Generate the invoice

```go
	inv, err := engine.GenerateInvoice(ctx, sub.ID)
	if err != nil {
		stdlog.Fatal(err)
	}
	fmt.Println("invoice", inv.ID, inv.Status)
	for _, li := range inv.LineItems {
		fmt.Printf("  %-8s %-22s qty=%-5d %s\n", li.Type, li.Description, li.Quantity, li.Amount)
	}
	fmt.Println("  subtotal", inv.Subtotal, "discount", inv.DiscountAmount, "tax", inv.TaxAmount, "total", inv.Total)
```

For this period the invoice has four lines:

| Line | Amount |
|------|--------|
| Base subscription fee | $49.99 |
| API calls overage, 650 calls at 2 cents | $13.00 |
| Seats, 3 at $10 | $30.00 |
| Discount LAUNCH10, 10% of $92.99 | $9.29 off |

The total is $83.70. A discount line carries a negative amount, which `Money.String` prints as `$-9.29`. A percentage coupon takes its share of the subtotal before any discount, rounded down to the cent. With no tax plugin registered there's no tax line.

## 8. Finalize, pay and cancel

```go
	if err := engine.FinalizeInvoice(ctx, inv.ID); err != nil {
		stdlog.Fatal(err)
	}
	if err := engine.MarkInvoicePaid(ctx, inv.ID, time.Now(), "pi_123"); err != nil {
		stdlog.Fatal(err)
	}

	// Cancel at the end of the current period. Pass true to cancel now.
	if err := engine.CancelSubscription(ctx, sub.ID, false); err != nil {
		stdlog.Fatal(err)
	}
	updated, err := engine.GetSubscription(ctx, sub.ID)
	if err != nil {
		stdlog.Fatal(err)
	}
	fmt.Println("cancels at", updated.CancelAt.Format(time.RFC3339))
}
```

`FinalizeInvoice` moves the draft to `pending` with a due date 30 days out. `MarkInvoicePaid` records the payment your provider collected. A scheduled cancel sets `CancelAt` to the period end and leaves the subscription running, and the lifecycle clock cancels it once that date passes.

## The whole program

```go
package main

import (
	"context"
	"fmt"
	stdlog "log"
	"time"

	"github.com/xraph/go-utils/log"

	"github.com/xraph/ledger"
	"github.com/xraph/ledger/coupon"
	"github.com/xraph/ledger/plan"
	"github.com/xraph/ledger/store/memory"
	"github.com/xraph/ledger/subscription"
	"github.com/xraph/ledger/types"
)

func main() {
	ctx := context.Background()

	engine := ledger.New(memory.New(),
		ledger.WithLogger(log.NewDevelopmentLogger()),
		ledger.WithMeterConfig(50, time.Second),
		ledger.WithEntitlementCacheTTL(30*time.Second),
	)
	if err := engine.Start(ctx); err != nil {
		stdlog.Fatal(err)
	}
	defer engine.Stop()

	run(ctx, engine)
}

func run(ctx context.Context, engine *ledger.Ledger) {

		Name:     "Pro",

				{FeatureKey: "api_calls", Type: plan.TierGraduated, UpTo: 10000, UnitAmount: types.Zero("usd")},

	if err := engine.CreatePlan(ctx, pro); err != nil {
```

## The flow

```
CreatePlan           the catalog: features, limits, a base fee, tiers
CreateSubscription   a tenant on a plan, with its first period
Meter                usage, buffered and flushed in batches
Entitled             the quota check on the request path
ApplyCoupon          a discount that stays on the subscription
GenerateInvoice      base, overage, seat, discount and tax lines for one period
FinalizeInvoice      draft to pending, due in 30 days
MarkInvoicePaid      the payment your provider collected
```
