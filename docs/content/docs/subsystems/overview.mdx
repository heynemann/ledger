---
title: Billing System Overview
description: The parts of Ledger's billing model and how a request and a billing period move through them.
---

Ledger splits billing into a few parts that share one plan. The plan says what a tenant gets and what it costs; everything else reads from it. That's the point of the design: the limit your API enforces and the allowance your invoice prices come from the same `plan.Feature`, so they can't drift apart.

## The parts

| Part | Package | Main type | What it does |
|------|---------|-----------|--------------|
| [Plans and pricing](/docs/subsystems/plans) | `plan` | `plan.Plan` | Features, limits, a base fee and price tiers |
| [Subscriptions](/docs/subsystems/subscriptions) | `subscription` | `subscription.Subscription` | A tenant on a plan, its period, trial, pause and cancel state |
| [Metering](/docs/subsystems/metering) | `meter` | `meter.UsageEvent` | Buffered, batched usage ingestion |
| [Entitlements](/docs/subsystems/entitlements) | `entitlement` | `entitlement.Result` | The quota check on the request path |
| [Invoicing](/docs/subsystems/invoicing) | `invoice` | `invoice.Invoice` | Line items for one period, priced from the plan |
| [Billing cycles](/docs/subsystems/billing-cycles) | `ledger` | `ledger.LifecycleReport` | The lifecycle clock that rolls periods, ends trials, enacts cancels |
| [Coupons](/docs/subsystems/coupons) | `coupon` | `coupon.Coupon` | Percentage and fixed-amount discounts |
| [Payment providers](/docs/subsystems/payments) | `provider` | `provider.Provider` | Your bridge to Stripe, Paddle or anything else |

Plans, subscriptions, invoices and coupons are stored entities with IDs. Usage events are append-only rows. Entitlement results are computed on demand and cached for a short time.

## A request

```
your handler
  ├── engine.Entitled(ctx, "api_calls")   active subscription → plan → feature → usage
  │       Allowed? no  → refuse the request
  │                yes → do the work
  └── engine.Meter(ctx, "api_calls", 1)   onto the buffer; the flush worker writes it
```

The tenant and app come from the context values `"tenant_id"` and `"app_id"`. See [Multi-tenancy](/docs/concepts/multi-tenancy).

## A billing period

```
CreateSubscription          period 1 starts now
   │  ... usage ...
   ▼
lifecycle clock             period 1 ends; the subscription moves to period 2
   │                        and OnSubscriptionRenewed lists period 1 as ended
   ▼
GenerateInvoice(ForPeriod)  you bill period 1: base fee, overage, seats,
   │                        discounts, tax
   ▼
FinalizeInvoice             pending, due in 30 days
   ▼
MarkInvoicePaid             once your provider has collected
                            (or the clock marks it past_due after the due date)
```

Ledger moves the period forward on its own, but it never bills it. You call `GenerateInvoice`, from an `OnSubscriptionRenewed` hook or your own scheduler.

## Money

Every amount is a `types.Money`: an `int64` in the currency's smallest unit and a lowercase currency code. There are no floats anywhere in pricing.

```go
price := types.USD(2999) // $29.99
```

## Identifiers

Every entity has a TypeID with a prefix: `plan_`, `feat_`, `sub_`, `uevt_`, `inv_`, `li_`, `cpn_` and so on. See [Identity](/docs/concepts/identity).
