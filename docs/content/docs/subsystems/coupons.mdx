---
title: Coupons
description: Percentage and fixed-amount coupons, how they're applied to a subscription, and how they discount its invoices.
---

A coupon is a discount you attach to a subscription by its code. Once applied, it discounts every invoice that subscription gets until you delete the coupon.

## Structure

```go
type Coupon struct {
	types.Entity
	ID             id.CouponID
	Code           string // unique within the app
	Name           string
	Type           CouponType  // percentage or amount
	Amount         types.Money // for amount coupons
	Percentage     int         // for percentage coupons, 0 to 100
	Currency       string
	MaxRedemptions int         // 0 or less means unlimited
	TimesRedeemed  int
	ValidFrom      *time.Time
	ValidUntil     *time.Time
	AppID          string
	Metadata       map[string]string
}
```

## Creating coupons

### Percentage

```go
c := &coupon.Coupon{
	Code:       "LAUNCH20",
	Name:       "Launch discount",
	Type:       coupon.CouponTypePercentage,
	Percentage: 20,
	AppID:      "my-app",
}
if err := engine.CreateCoupon(ctx, c); err != nil {
	return err
}
```

### Fixed amount

```go
c := &coupon.Coupon{
	Code:           "TENOFF",
	Name:           "$10 off",
	Type:           coupon.CouponTypeAmount,
	Amount:         types.USD(1000),
	MaxRedemptions: 100,
	AppID:          "my-app",
}
```

An amount coupon needs a currency: the `Amount`'s own, or `Currency` when the amount carries none.

`CreateCoupon` trims the code, lowercases the currencies, assigns a `cpn_` ID, sets `TimesRedeemed` to 0, and refuses:

- a missing code, an unknown type, a percentage outside 0 to 100, a negative amount, or an amount coupon with no currency (`ErrCouponInvalid`);
- a `ValidUntil` before `ValidFrom` (`ErrCouponInvalid`);
- a code the app already uses (`ErrAlreadyExists`).

## Validity windows

`ValidFrom` and `ValidUntil` are optional. They're checked when you apply the coupon, against the engine's clock. Applying it before `ValidFrom` fails with `ErrCouponNotStarted`, and after `ValidUntil` with `ErrCouponExpired`.

The window limits when a coupon can be applied, not how long it discounts. A coupon applied inside its window keeps discounting after `ValidUntil`.

## Applying a coupon

```go
applied, err := engine.ApplyCoupon(ctx, sub.ID, "LAUNCH20")
```

`ApplyCoupon` looks the code up in the subscription's app and checks, before writing anything:

1. the validity window;
2. the redemption cap (`ErrCouponExhausted`);
3. the coupon's shape, as `CreateCoupon` does;
4. the currency: an amount coupon must be in the plan's currency, and a percentage coupon with a `Currency` set must match it too (`ErrCouponInvalid`);
5. every `CouponValidator` plugin (a refusal wraps `ErrCouponInvalid`).

Then the store records the application and increments `TimesRedeemed` as one unit, enforcing the cap again so two concurrent redemptions can't both take the last slot. Applying the same coupon to the same subscription twice fails with `ErrCouponAlreadyApplied`. It returns the coupon with its new count.

A coupon can sit on many subscriptions, and a subscription can carry many coupons. `ListAppliedCoupons(ctx, subID)` returns a subscription's coupons, oldest first.

## How a coupon discounts an invoice

`GenerateInvoice` adds one `discount` line per applied coupon, as a negative amount:

- A percentage coupon takes its percentage of the subtotal (base, overage and seats) before any discount. Two percentage coupons each take their share of the same subtotal, so 10% and 20% give 30% off, not 28%. The amount is rounded down to the cent.
- An amount coupon takes its amount off.

The discounts are summed into `DiscountAmount`, and the total never drops below zero. Tax is computed after discounts. Each coupon is validated again at that point, so a coupon whose currency no longer matches the plan fails the invoice with `ErrCouponInvalid`.

## Changing and removing coupons

```go
c.Name = "Spring launch"
c.MaxRedemptions = 500
err := engine.UpdateCoupon(ctx, c)
```

`UpdateCoupon` changes the name, the redemption cap, the validity window and the metadata. The code, type, value, currency and app are fixed once created, and changing any of them fails with `ErrCouponInvalid`. The redemption count is never written by an update.

`DeleteCoupon(ctx, couponID)` removes the coupon, and the subscriptions it was applied to stop getting its discount from their next invoice. There's no way to detach a coupon from one subscription only.

## Listing coupons

```go
all, err := engine.Store().ListCoupons(ctx, "my-app", coupon.ListOpts{})
byCode, err := engine.Store().GetCoupon(ctx, "LAUNCH20", "my-app")
```

## Remote access

Ledger has no HTTP routes for coupons. The Forge dashboard uses the contract intents `coupons.list`, `coupons.detail`, `coupons.create`, `coupons.update`, `coupons.delete` and `coupons.apply`. See [HTTP API](/docs/api-reference/http-api).
